Open Library API: Search for Books and Authors

The Open Library API gives you access to one of the largest open book databases in the world. Maintained by the Internet Archive, it's freely available with no authentication required for the use cases in this tutorial.

This tutorial walks you through the core research workflow:

  1. Search for a book by title, author, or keyword.
  2. Retrieve full metadata for a specific work.
  3. Look up an author's biography and other works.

Prerequisites​

Before you begin, make sure you have the following:

  • An HTTP client. This tutorial shows requests using curl. You can also use Postman or any client that sends HTTP requests.
  • An internet connection. No API key or account is required.
  • Familiarity with JSON. All API responses return JSON.

Base URLs​

This tutorial uses two base URLs:

ServiceBase URL
Search, works, authors, editionshttps://openlibrary.org
Cover imageshttps://covers.openlibrary.org

All endpoint paths in this tutorial are appended to the relevant base URL.

Step 1: Search for a book​

Use the search endpoint to find a book by title, author, or keyword.

Use the endpoint​

GET https://openlibrary.org/search.json

Send the request​

The following request searches for the Republic:

curl "https://openlibrary.org/search.json?q=republic"

To narrow your results, combine query parameters:

curl "https://openlibrary.org/search.json?author=plato&title=republic&limit=5"
ParameterExampleDescription
qq=republicGeneral keyword search
authorauthor=platoFilter by author name
titletitle=republicFilter by title
limitlimit=5Maximum number of results to return

Interpret the response​

A successful request returns 200 OK with a JSON body. The following example shows a partial response for the query ?q=republic:

{
  "numFound": 165016,
  "start": 0,
  "q": "republic",
  "docs": [
    {
      "author_key": [
        "OL12823A"
      ],
      "author_name": [
        "Plato"
      ],
      "cover_i": 14418448,
      "ebook_access": "public",
      "edition_count": 794,
      "first_publish_year": 1554,
      "key": "/works/OL51831W",
      "title": "πολιτεία"
    }
  ]
}
FieldTypeDescription
numFoundintegerTotal number of matching works
docsarrayWorks matching your search query
docs[].author_keyarrayUnique identifiers for each author — use these in Step 3
docs[].author_namearrayMay appear in a non-Latin script
docs[].cover_iintegerA single cover image ID for this work, available directly from search results — see Display cover images and author photos
docs[].ebook_accessstringWhether the full text is publicly accessible (see below)
docs[].edition_countintegerA higher count generally reflects a longer publication history
docs[].keystringUnique identifier for the work — use this in Step 2
docs[].titlestringMay appear in a non-Latin script

Handle non-Latin characters. Text fields, including author_name and title, are stored exactly as they appear in the Open Library database and often use their original scripts. For example, searching for "republic" may return "title": "πολιτεία" — the ancient Greek form. Make sure your application can handle and display non-Latin characters in these fields.

Understand ebook_access values.

ValueDescription
publicFully accessible — no restrictions
borrowableAvailable through the Internet Archive's lending program
printdisabledAccessible only to users with print disabilities
no_ebookNo digital version available

Ancient Greek and Latin works are in the public domain, but modern translations are not. A recent English translation of the Republic will likely return "ebook_access": "borrowable" even though Plato's original text is thousands of years old.

Save the key value from your first result — for example, /works/OL51831W. You'll use it in Step 2: Retrieve a specific work.

Error responses​

Status codeCauseWhat to do
400 Bad RequestA query parameter is malformedCheck your parameter names and values
503 Service UnavailableOpen Library is temporarily unavailableRetry with exponential backoff

Step 2: Retrieve a specific work​

Use the work key from Step 1 to retrieve full metadata for that work.

Use the endpoint​

GET https://openlibrary.org/works/{work_id}.json

Replace {work_id} with the identifier from the key field in your Step 1 results — for example, OL51831W.

Send the request​

curl "https://openlibrary.org/works/OL51831W.json"

Interpret the response​

A successful request returns 200 OK. The following example shows a partial response for the Republic (OL51831W):

{
  "description": "The Republic is Plato's most famous work and one of the seminal texts of Western philosophy...",
  "authors": [
    {
      "author": { "key": "/authors/OL12823A" },
      "type": { "key": "/type/author_role" }
    }
  ],
  "covers": [14418448],
  "first_publish_date": "1963",
  "key": "/works/OL51831W",
  "subject_people": ["Plato", "Platōn"],
  "subject_times": ["Early works to 1800", "Ouvrages avant 1800"],
  "subjects": ["Political science", "Justice"],
  "title": "πολιτεία"
}
FieldDescription
descriptionA summary of the work — see format note below
authorsAuthor references — each contains a key you'll use in Step 3
coversCover image IDs — see Display cover images and author photos
subject_peopleHistorical figures referenced in the work — may contain duplicates
subject_timesHistorical periods associated with the work — may contain duplicates

Handle two description formats. The description field returns either a plain string or an object:

"description": "The Republic is Plato's most famous work..."
"description": {
  "type": "/type/text",
  "value": "The Republic is Plato's most famous work..."
}

Check the type before accessing the value, or your application will throw an unexpected error on one of the two formats.

Handle duplicate subject_people and subject_times entries. Both fields aggregate data from multiple library cataloging traditions, so the same entity often appears more than once in different formats or languages:

"subject_people": [
  "Plato",
  "Platōn (427-347 p.Ch)",
  "Platon (0427?-0348? av. J.-C.)."
]

De-duplicate or group these entries before displaying them in your UI.

Save the author key from the authors array — for example, /authors/OL12823A. You'll use it in Step 3: Retrieve author details.

Error responses​

Status codeCauseWhat to do
404 Not FoundThe work ID does not exist in Open LibraryConfirm the ID came from a Step 1 search response
503 Service UnavailableOpen Library is temporarily unavailableRetry with exponential backoff

Step 3: Retrieve author details​

Use the author key from Step 2 to retrieve the author's biography, dates, and external identifiers.

Use the endpoint​

GET https://openlibrary.org/authors/{author_id}.json

Replace {author_id} with the identifier from the authors[].author.key field in your Step 2 response — for example, OL12823A.

Send the request​

curl "https://openlibrary.org/authors/OL12823A.json"

Interpret the response​

A successful request returns 200 OK. The following example shows a truncated response:

{
  "alternate_names": [
    "Πλάτων",
    "Platon",
    "Platōn",
    "Platón",
    "Platone"
  ],
  "remote_ids": {
    "wikidata": "Q859",
    "project_gutenberg": "93"
  },
  "photos": [
    6457448,
    3366955,
    6319952,
    6319966,
    -1
  ],
  "death_date": "348/347 BC",
  "bio": "Classical Greek philosopher",
  "name": "Plato",
  "birth_date": "428/427 BC"
}
FieldDescription
alternate_namesOther names the author is known by, including non-Latin scripts
remote_idsCross-references to external databases (see below)
photosAuthor photo IDs — see Display cover images and author photos. A value of -1 means no photo exists; filter it out before building a URL
death_dateDate of death — format varies; may be absent
bioA biography — may be a plain string or an object, the same dual-format issue as description in Step 2
nameThe author's full name
birth_dateDate of birth — format varies; may be approximate or absent for ancient authors

Use remote_ids to link to external sources. This field is particularly useful for a research tool — it lets you link an author profile to authoritative external databases without additional searching:

IdentifierDescription
project_gutenbergLinks to freely accessible texts on Project Gutenberg
wikidataLinks to Wikidata's multilingual structured knowledge base

Not every author has all identifiers populated. Check for the existence of each field before using it.

Handle missing fields gracefully. For ancient authors, many fields — including bio, birth_date, and death_date — may be null or absent. Your application must handle both null and missing fields without throwing an error.

Retrieve all works by an author​

Once you have the author key, retrieve all works associated with that author:

curl "https://openlibrary.org/authors/OL12823A/works.json"

This lets a researcher start from a single text and discover an author's entire body of work in one request.

Error responses​

Status codeCauseWhat to do
404 Not FoundThe author ID does not exist in Open LibraryConfirm the ID came from a Step 2 work response
503 Service UnavailableOpen Library is temporarily unavailableRetry with exponential backoff

Next steps​

Now that you've completed the core workflow, here are some ways to extend your integration.

Explore subjects and topics​

Browse all works under a subject category using the subjects endpoint:

curl "https://openlibrary.org/subjects/ancient_greek_literature.json"

This opens up category-level browsing — users can explore an entire literary tradition without knowing specific titles.

Handle inconsistent subject taxonomy. Open Library's subject tags are community-contributed. The same body of literature may be cataloged under different tags depending on who added the record:

Tag
greek_literature
classical_literature
ancient_philosophy
ancient_greek_literature

For comprehensive results, run parallel requests across multiple subject endpoints and merge the results in your application.

Retrieve editions of a work​

Works and editions are separate in Open Library. A work is the abstract text — the Republic. An edition is a specific published version — an Oxford Classics translation with a particular ISBN and page count.

To retrieve all editions of a work, use the work key from Step 2:

curl "https://openlibrary.org/works/OL51831W/editions.json"

Use the work key, not the author key. Passing an author key to this endpoint returns 404 Not Found. Always verify which key type you're working with before constructing a request.

Display cover images and author photos​

Both works and authors can have associated images. Works have cover images (from the covers field in Step 2); authors have photos (from the photos field in Step 3). Both use the same image endpoint and ID pattern.

GET https://covers.openlibrary.org/b/id/{id}-{size}.jpg

Replace {id} with a numeric ID from the covers array (Step 2) or the photos array (Step 3). Replace {size} with one of the following:

ValueDescription
SSmall
MMedium
LLarge

Display a work's cover image. Use a numeric ID from the work's covers array — for example, 14418448:

curl "https://covers.openlibrary.org/b/id/14418448-M.jpg" --output cover.jpg

Display an author's photo. Use a numeric ID from the author's photos array — for example, 6457448:

curl "https://covers.openlibrary.org/b/id/6457448-M.jpg" --output photo.jpg

Handle missing photos. Unlike covers, the photos array can contain -1 as a placeholder when no photo exists:

"photos": [6457448, 3366955, -1]

Filter out any -1 value before constructing an image URL, or the request will return a generic "image not found" placeholder instead of failing cleanly.

Search by ISBN​

If your users already know a book's ISBN, retrieve the specific edition directly:

curl "https://openlibrary.org/isbn/9780140275360.json"

This returns the edition associated with that ISBN — more precise than a keyword search when the exact publication matters.

Handle missing and inconsistently formatted data​

As you saw in Step 2 and Step 3, some fields are inconsistently formatted or absent entirely. Before shipping an integration, make sure your application handles the following cases:

CaseFields affected
Field returns a plain string or an objectdescription, bio
Field is null or absent entirelybio, birth_date, death_date, covers, description
Work has no associated authorsauthors
subject_people or subject_times contain duplicates in multiple languagessubject_people, subject_times
