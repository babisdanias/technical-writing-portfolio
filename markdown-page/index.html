Open Library API: Search for Books and Authors

The Open Library API gives you access to one of the largest open book databases in the world. Maintained by the Internet Archive, it's freely available with no authentication required for the use cases in this tutorial.

This tutorial walks you through the core research workflow:

  1. Search for a book by title, author, or keyword.
  2. Retrieve full metadata for a specific work.
  3. Look up an author's biography and other works.

Prerequisites​

Before you begin, make sure you have the following:

  • An HTTP client. This tutorial shows requests using curl. You can also use Postman or any client that sends HTTP requests.
  • An internet connection. No API key or account is required.
  • Familiarity with JSON. All API responses return JSON.

Base URLs​

This tutorial uses two base URLs:

ServiceBase URL
Search, works, authors, editionshttps://openlibrary.org
Cover imageshttps://covers.openlibrary.org

All endpoint paths in this tutorial are appended to the relevant base URL.

Step 1: Search for a book​

Use the search endpoint to find a book by title, author, or keyword.

Use the endpoint​

GET https://openlibrary.org/search.json

Send the request​

The following request searches for the Iliad:

curl "https://openlibrary.org/search.json?q=iliad"

To narrow your results, combine query parameters:

curl "https://openlibrary.org/search.json?author=homer&title=iliad&limit=5"
ParameterExampleDescription
qq=iliadGeneral keyword search
authorauthor=homerFilter by author name
titletitle=iliadFilter by title
limitlimit=5Maximum number of results to return

Interpret the response​

A successful request returns 200 OK with a JSON body. The following example shows a truncated response for the query ?q=iliad:

{
  "numFound": 842,
  "docs": [
    {
      "key": "/works/OL51831W",
      "title": "Iliad",
      "author_key": ["OL2537771A"],
      "author_name": ["Όμηρος"],
      "first_publish_year": 1489,
      "edition_count": 842,
      "ebook_access": "public"
    }
  ]
}
FieldTypeDescription
numFoundintegerTotal number of matching works
docsarrayWorks matching your search query
docs[].keystringUnique identifier for the work — use this in Step 2
docs[].author_keyarrayUnique identifiers for each author — use these in Step 3
docs[].author_namearrayAuthor names as stored in Open Library
docs[].edition_countintegerNumber of known editions
docs[].first_publish_yearintegerYear the work was first published
docs[].ebook_accessstringWhether the full text is publicly accessible (see below)

Handle non-Latin author names. Author names are stored as they appear in Open Library's database and may be in their original script. Searching for "Homer" may return "author_name": ["Όμηρος"] — the ancient Greek form. Make sure your application handles non-Latin characters in this field.

Understand ebook_access values.

ValueDescription
publicFully accessible — no restrictions
borrowableAvailable through the Internet Archive's lending program
printdisabledAccessible only to users with print disabilities
no_ebookNo digital version available

Ancient Greek and Latin works are in the public domain, but modern translations are not. A recent English translation of the Iliad will likely return "ebook_access": "borrowable" even though Homer's original text is thousands of years old.

Save the key value from your first result — for example, /works/OL51831W. You'll use it in Step 2.

Error responses​

Status codeCauseWhat to do
400 Bad RequestA query parameter is malformedCheck your parameter names and values
503 Service UnavailableOpen Library is temporarily unavailableRetry with exponential backoff

Step 2: Retrieve a specific work​

Use the work key from Step 1 to retrieve full metadata for that work.

Use the endpoint​

GET https://openlibrary.org/works/{work_id}.json

Replace {work_id} with the identifier from the key field in your Step 1 results — for example, OL51831W.

Send the request​

curl "https://openlibrary.org/works/OL51831W.json"

Interpret the response​

A successful request returns 200 OK. The following example shows a truncated response for the Iliad (OL51831W):

{
  "key": "/works/OL51831W",
  "title": "Iliad",
  "description": {
    "type": "/type/text",
    "value": "The Iliad is an ancient Greek epic poem attributed to Homer..."
  },
  "authors": [
    {
      "author": { "key": "/authors/OL2537771A" },
      "type": { "key": "/type/author_role" }
    }
  ],
  "covers": [7353305],
  "first_publish_date": "1489",
  "subjects": ["Epic poetry, Greek", "Trojan War"],
  "subject_people": ["Achilles", "Hector"],
  "subject_times": ["Trojan War", "Guerre de Troie"]
}
FieldDescription
titleThe title of the work — may appear in a non-Latin script
descriptionA summary of the work — see format note below
authorsAuthor references — each contains a key you'll use in Step 3
coversCover image IDs — use these to retrieve cover images
first_publish_dateYear the work was first published
subject_peopleHistorical figures referenced in the work — may contain duplicates
subject_timesHistorical periods associated with the work — may contain duplicates

Handle two description formats. The description field returns either a plain string or an object:

"description": "The Iliad is an ancient Greek epic poem..."
"description": {
  "type": "/type/text",
  "value": "The Iliad is an ancient Greek epic poem..."
}

Check the type before accessing the value, or your application will throw an unexpected error on one of the two formats.

Handle duplicate subject_people and subject_times entries. Both fields aggregate data from multiple library cataloging traditions, so the same entity often appears more than once in different formats or languages:

"subject_people": [
  "Plato",
  "Platōn (427-347 p.Ch)",
  "Platon (0427?-0348? av. J.-C.)."
]

De duplicate or group these entries before displaying them in your UI.

Save the author key from the authors array — for example, /authors/OL2537771A. You'll use it in Step 3.

Error responses​

Status codeCauseWhat to do
404 Not FoundThe work ID does not exist in Open LibraryConfirm the ID came from a Step 1 search response
503 Service UnavailableOpen Library is temporarily unavailableRetry with exponential backoff

Step 3: Retrieve author details​

Use the author key from Step 2 to retrieve the author's biography, dates, and external identifiers.

Use the endpoint​

GET https://openlibrary.org/authors/{author_id}.json

Replace {author_id} with the identifier from the authors[].author.key field in your Step 2 response — for example, OL2537771A.

Send the request​

curl "https://openlibrary.org/authors/OL2537771A.json"

Interpret the response​

A successful request returns 200 OK. The following example shows a truncated response:

{
  "name": "Homer",
  "alternate_names": ["Όμηρος", "Homère", "Homero"],
  "birth_date": "850 BC",
  "death_date": "unknown",
  "bio": {
    "type": "/type/text",
    "value": "Homer is the presumed author of the Iliad and the Odyssey..."
  },
  "remote_ids": {
    "wikidata": "Q6691",
    "project_gutenberg": "1426",
    "lc_naf": "n78095639"
  }
}
FieldDescription
nameThe author's full name
alternate_namesOther names the author is known by, including non-Latin scripts
birth_dateDate of birth — format varies; may be approximate or absent for ancient authors
death_dateDate of death — format varies; may be absent
bioA biography — may be a plain string or an object (see note in Step 2)
remote_idsCross-references to external databases (see below)

Use remote_ids to link to external sources. This field is particularly useful for a research tool — it lets you link an author profile to authoritative external databases without additional searching:

IdentifierDescription
project_gutenbergLinks to freely accessible texts on Project Gutenberg
wikidataLinks to Wikidata's multilingual structured knowledge base
lc_nafLibrary of Congress authority record, used widely in academic citation

Not every author has all identifiers populated. Check for the existence of each field before using it.

Handle missing fields gracefully. For ancient authors, many fields — including bio, birth_date, and death_date — may be null or absent. Your application must handle both null and missing fields without throwing an error.

Retrieve all works by an author​

Once you have the author key, retrieve all works associated with that author:

curl "https://openlibrary.org/authors/OL2537771A/works.json"

This lets a researcher start from a single text and discover an author's entire body of work in one request.
